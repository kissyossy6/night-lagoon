# プロジェクト単位で管理する（スタート → 一覧 → エディタ → 本番再生）

2026-11-11 作成。同日、§5 のおすすめ（ディスクの `projects/`・見本はすぐ複製・サムネイル付きのカード）で作った。画面のつながりは [screen-flow.html](screen-flow.html)。

追加で決めたこと：
- **GitHub に個人データを入れない**。`.gitignore` で `projects/*` を外し、`!projects/sample-*/` で見本だけ残す。見本は「ドロップフォルダ」：`projects/sample-…` を置けば見本になる（一覧の ⋯ →「見本にする」でも作れる）
- `edit.html` を `?project` なしで開くと**確認用**（前と同じ1枠の自動保存。確認の scripts がこれを使う）。どのプロジェクトにも書かない
- 見本の絵とスタート画面の背景（`public/home-bg.jpg`）は `scripts/home-assets.mjs` で撮る

---

## 0. 結論（先に）

> 今は「開く＝いきなり本番のショー」。これを、ふつうの制作ツールの順番に並べ直す。
>
> **スタート**（今の画面のまま） → **［プロジェクト一覧］** → 1つ選ぶ → **エディタ** → **［本番で再生］**
>
> 1. ショーを**プロジェクト**という単位で持つ。1プロジェクト＝演出1つ（会場はその中の `venue` で指す）
> 2. スタート画面の見た目はそのまま。「ショーを始める」ボタンを **「プロジェクト一覧」** にする
> 3. プロジェクトを開くと**エディタ**。本番の再生は**エディタから**（今の「本番で見る」を正式な入口にする）
> 4. 今の3つの版（Night Lagoon・ファンタジア・花火）は一覧の**「見本」**として残す
> 5. 保存先は**ディスクの `projects/` フォルダ**（1プロジェクト1フォルダ）。ブラウザの中だけに置かない

## 1. 今の作りと、何が違和感か

| 所 | 今 | 困ること |
| --- | --- | --- |
| `index.html`（`src/show/main.ts`） | 開くとスタート画面。「ショーを始める」で**組み込みのショー**が再生される。裏ではもう 3D と音楽の解析が動いている | 作品を選ぶ前に再生が始まる。どの作品かを選ぶ場所が無い |
| `?show=lagoon/fantasia/hanabi/edited` | URL の文字で版を切り替える | 利用者には見えない。URL を知らないと選べない |
| `edit.html`（`src/editor/main.ts`） | `localStorage` の **1枠**（`water-show-editor:v1`）に自動保存 | 作品は同時に1つしか持てない。別の版を「読み込む」と上書き（元に戻す1回分だけ残る） |
| エディタ「本番で見る」 | 自動保存を流してから `/?show=edited` を新しいタブで開く | 入口がエディタの中の小さなボタン。本番画面の「エディタ ↗」は**どの作品か**を持たずに戻る |
| `venue.html` の「3Dで見る」 | `?show=edited` があれば付ける | 「エディタの今の演出」という1枠が前提 |

## 2. できあがりの流れ

```
 /  スタート（今の見た目）
 │   Night Lagoon / 夜の湖の噴水ショー
 │   ［ プロジェクト一覧 ］
 ▼
 /  プロジェクト一覧（同じページで切り替え）
 │   ＋新規   JSON を読み込む
 │   ┌ 自分のプロジェクト（更新が新しい順）┐
 │   │ [絵] 夏祭り版  ・湖・3:37・3日前   ⋯ │
 │   └────────────────────────────┘
 │   見本：Night Lagoon / ファンタジア版 / 花火版
 ▼ クリック
 /edit.html?project=<id>   エディタ
 │   ← 一覧   夏祭り版（名前はその場で直せる）   …   ［▶ 本番で再生］
 ▼
 /play.html?project=<id>   本番再生
     題名＋［▶ 再生］（音を鳴らすのにクリックが要るため、ここで1回押す）
     下のバー：今と同じ（カメラ・表示・動画を書き出す）＋「← エディタに戻る」
```

### 2.1 スタート画面
- 見た目・文言はそのまま（背景のグラデーション、題、説明）
- 「ショーを始める」→ **「プロジェクト一覧」**。準備中の待ち（音楽の読み込み）が要らなくなるので、最初から押せる
- 「音楽ファイルを選ぶ」はスタート画面から外し、本番再生の画面に移す（その場で音を差し替える用途のため。§6 参照）
- スタート画面では **3D を作らない**。今は裏で噴水と音楽の解析が走っているが、見えていないので無駄。開くのが速くなる

### 2.2 プロジェクト一覧
- スタート画面と同じページ（`index.html`）で、ボタンで切り替える（同じ背景の上に一覧が出る）。ブラウザの戻るで戻れるように `#projects` を付ける
- 1行（またはカード）に：**サムネイル**・名前・会場・長さ・更新日時
- クリックで**エディタを開く**。⋯ メニューに：名前を変える／複製／JSON を書き出す／削除（確認あり）
- 上に「＋ 新規」：**空のショー** か **見本から**（Night Lagoon・ファンタジア版・花火版）を選ぶ。名前を付けて作るとそのままエディタへ
- 「JSON を読み込む」：今のエディタの JSON 読み込みと同じ形式を、新しいプロジェクトとして取り込む
- 0件のとき：「まだプロジェクトがありません」＋見本から作るボタン
- 見た目はデザイン文法（web）に合わせる：アクセント色1つ、文字は 4〜6段階、余白は 8 の倍数、影なし・1px の線、角丸は1種類。値は `src/styles/tokens.css` から取る（新しい色を足さない）

### 2.3 エディタ
- URL は `edit.html?project=<id>`。`project` が無ければ一覧へ戻す（または最後に開いたプロジェクト）
- 左上：「水上ショー エディタ」の代わりに **「← 一覧」＋プロジェクト名**（クリックで名前を直す）
- 自動保存の行き先をそのプロジェクトに。今の「自動保存済み」表示はそのまま
- 「本番で見る」→ **「▶ 本番で再生」** として右上の目立つ位置へ。`play.html?project=<id>` を開く（同じ名前の窓を使い回し、何枚も開かない）
- ファイル ▾ の並べ直し：
  - 残す：JSON を書き出す／JSON を読み込む（このプロジェクトに上書き。元に戻せる）
  - 足す：複製して別のプロジェクトにする
  - 移す：「新規ショー」「〇〇を読み込む」は一覧の「＋ 新規」へ。エディタの中では「見本で置き換える」として残す（元に戻せる）
- 閉じる・一覧に戻るときに保存とサムネイルを確定させる

### 2.4 本番再生
- 新しいページ `play.html`（中身は今の `src/show/main.ts`）。URL は `play.html?project=<id>`
- 開くと題（プロジェクト名）と **［▶ 再生］**。ブラウザは音をクリックなしで鳴らせないので、この1回は残す。ここは「作品を見る前の幕」として自然な形
- バーの「エディタ ↗」→ **「← エディタに戻る」**（同じプロジェクトへ）
- `?show=lagoon/fantasia/hanabi/test/pyrotest`・`?shot`・`?t`・`?venue` などの今の引数は**そのまま使える**ようにする（確認用の scripts がこれで動いているため）

## 3. プロジェクトの中身と保存先

### 3.1 保存先：ディスクの `projects/` フォルダ（おすすめ）

```
projects/
  <id>/
    project.json   名前・作成日時・更新日時・演出（ShowFile）
    thumb.jpg      一覧のサムネイル（エディタの 3D から撮る）
```

- 開発サーバーに小さなプラグイン `scripts/project-store.ts` を足し、`/api/projects` で一覧・読む・書く・消すをする（`exports/` を書いている `video-store.ts`・`control-store.ts` と同じやり方）
- 理由：
  - ブラウザの記録（`localStorage`）だけだと、ブラウザを替えたり記録を消したりすると**作品が消える**。容量も約 5MB で、数作品で足りなくなる
  - フォルダなら Finder で見える・バックアップできる・git に入れられる。「値と素材は1か所に、置き場のフォルダで」という方針に合う
  - 後でプロジェクトごとの音楽（§6）を置く場所にもなる
- 開発サーバー無しで開いたとき（`dist` を静的に置いたとき）は、ブラウザの記録に置く**予備**の動きにする（一覧の上に「この環境ではブラウザに保存しています」と出す）
- 削除は**ゴミ箱扱い**：`projects/.trash/` に移すだけにし、ディスクからは消さない

### 3.2 `project.json` の形

```jsonc
{
  "format": 1,
  "id": "p-20261111-a3f9",      // フォルダ名と同じ。作った日時＋短い乱数
  "name": "夏祭り版",
  "created": "2026-11-11T10:00:00+09:00",
  "updated": "2026-11-11T12:34:00+09:00",
  "from": "hanabi",              // 見本から作ったときの見本（無ければ空）
  "show": { /* 今の ShowFile そのまま（venue・cues・sections …） */ }
}
```

- 演出ファイル（`ShowFile`）の形は**変えない**。プロジェクトはそれを包むだけ
- 会場は今どおり**共通の会場一覧**から `show.venue` で指す（会場はプロジェクト間で使い回すもの）

### 3.3 見本（今の3つの版）の扱い
- 見本はコード（`buildShow` と `SHOW_VARIANTS`）が音楽の波形から作るもの。ファイルではない
- 一覧の「見本」から開くと、**その見本の複製を新しいプロジェクトとして作ってから**エディタを開く。見本そのものは書き換わらない
- 見本の再生だけしたい場合は、今の `play.html?show=hanabi` のまま（確認用）

### 3.4 今の自動保存の引っ越し
- 初めて一覧を開いたとき、`water-show-editor:v1` に中身があれば、**「エディタの演出（引っ越し）」**というプロジェクトを1つ作って移す。元の記録は消さずに残す（1回だけ・印を付ける）

## 4. 進め方（段階）

| 段 | 内容 | 主に触るファイル | 終わりの確かめ |
| --- | --- | --- | --- |
| **1. 保存の土台** | `projects/` の読み書き（開発サーバーのプラグイン＋ブラウザ側の `src/projects/store.ts`）、ブラウザ保存の予備、ゴミ箱、引っ越し | `scripts/project-store.ts`（新）・`vite.config.ts`・`src/projects/`（新） | 作る・読む・名前変更・複製・削除が API で通る |
| **2. ページの分け直し** | 今の本番画面を `play.html` に移す。`index.html` はスタート＋一覧だけにし 3D を作らない。`/?show=…` などで開かれたら `play.html` へ転送 | `index.html`・`play.html`（新）・`src/show/main.ts`・`src/home/`（新）・`vite.config.ts` の入口 | 今の scripts（`player-check.mjs` ほか）がそのまま通る |
| **3. 一覧画面** | スタートのボタンを「プロジェクト一覧」に。一覧・新規（空／見本から）・⋯メニュー・JSON 読み込み・0件の表示 | `src/home/`・`src/styles/home.css`（新） | 見本から作る → 一覧に出る → 名前変更・複製・削除 |
| **4. エディタをプロジェクトに** | `?project=` で開いて保存。左上に「← 一覧」と名前。ファイル ▾ の並べ直し。サムネイル撮影 | `src/editor/main.ts`・`edit.html`・`src/editor/editor.css` | 2つのプロジェクトを行き来しても混ざらない |
| **5. 本番再生をプロジェクトに** | `play.html?project=` で読む。題・▶再生・「← エディタに戻る」。エディタの「▶ 本番で再生」 | `src/show/main.ts`・`play.html`・`src/styles/player.css` | エディタで直す → 本番で再生 → 戻る、が1つのプロジェクトで閉じる |
| **6. まわり** | `venue.html` の「3Dで見る」と「狙う台が無いキュー」の数を全プロジェクト対象に。確認用 scripts・マニュアル（`docs/manual`）の更新 | `src/venues/editor/main.ts`・`scripts/*`・`docs/manual/index.html` | 会場エディタからも、選んだプロジェクトで 3D が開く |

- 各段の終わりに `pnpm typecheck` と、関係する確認 scripts を通す
- 段 3 の画面は作ったあと design-reviewer で見比べて直す
- 段 1〜2 は見た目が変わらない下ごしらえ。目に見えて変わるのは段 3 から

## 5. 決めてほしいこと（おすすめ付き）

1. **保存先**：ディスクの `projects/` フォルダ（おすすめ）か、今どおりブラウザの中だけか
2. **見本を開いたとき**：すぐ複製して自分のプロジェクトにする（おすすめ。誤って見本を変えない）か、見本のまま開いて最初の変更で複製するか
3. **一覧の形**：サムネイル付きのカード（おすすめ。噴水は絵で見分けるほうが早い）か、名前の並ぶ表か

## 6. 今回はやらないこと（後の段）

- **プロジェクトごとの音楽**。今は曲が1つ（`public/music/background.mp3`）で、長さ `SHOW_DURATION`（217 秒）も曲の区間も `src/show/song.ts` に固定。曲をプロジェクトごとに持つには、長さ・拍・区間をプロジェクト側に移す大きめの作業になる。保存先を `projects/<id>/` にしておけば、後でそこに曲を置ける
- **プロジェクトごとの会場の複製**。会場は今どおり共通（`venue.html` で作るもの）
- 一覧での検索・並べ替え・タグ（作品が十数個を超えたら考える）
