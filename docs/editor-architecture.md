# エディタの構成（1つのエディタで続けるか、分けるか）

2026-11-03 作成。コードはまだ変えていない。考えの整理と、おすすめの形の基本設計まで。
背景は [handoff.md](handoff.md)、要件は [dev-plan.md](dev-plan.md)（「1. 軸と範囲」「C. エディタの使い勝手」）。

---

## 0. 結論（先に）

> **エディタは1つのまま、演出ファイルも1つ、時間軸も1本。** そのうえで、
> 1. 行を**演出の種類ごとのフォルダ**（水・水幕・花火・照明・レーザー・炎・映像）にまとめ、たためるようにする
> 2. 時間軸の上に**作業画面のタブ**（全体・水・光・花火…）を置く。タブは「どのフォルダを開くか、3D で何を見せるか」の組を切り替えるだけで、別のエディタではない
> 3. **時間と関係ない仕事**（会場の機材配置、DMX の割り当て、書き出し）は**別のページ**にする。同じ演出・同じ会場を開く
> 4. 演出の種類を足すときは、**機材の種類の表**（1か所）に1つ足せば、行・インスペクター・判定・書き出しが付いてくる作りにする

一言でいうと「**Depence の時間軸（1本、たためる木）＋ grandMA3 の画面の切り替え（中身は同じ）＋ Resolve のページ（時間軸と関係ない仕事だけ）**」。

1つのエディタで**できる**。忖度なしで見ても、この規模（個人・1人で全部作る）では、分けるほうが損が大きい。ただし「今の作りのまま行を足していく」のは**続かない**ので、上の 1・4 は照明やレーザーを足す**前に**入れる必要がある。

## 1. 今の作りと、このまま行くと困ること

### 1.1 今の作り（ざっと見た範囲）

| 所 | 今 |
| --- | --- |
| 演出ファイル（`src/show/types.ts`） | `ShowFile` は時刻つきの `Cue` の一覧。キューは `target`（機材の並び）＋次のどれか：`set`／`macro`（水と LED の値）、`clip`（水幕の映像）、`fire`（花火） |
| 値の種類 | `Params` は噴水の5つ（pressure・pan・tilt・color・intensity）で固定 |
| 行（`src/editor/model.ts` の `LANES`） | 会場（`src/venues/lagoon.ts`）の `lanes` そのまま。1行＝1つの機材グループ。今は9行（グリッド〜ガイザー6、水幕2、花火1） |
| 時間軸（`timeline.ts`） | 1行の中で重なるキューは段を増やして並べる（1段 21px）。たたむ・隠す・ソロは無い |
| インスペクター（`inspector.ts`） | `isScreenLane`・`isPyroLane`・`cue.fire` などで種類ごとに枝分かれして作っている |

### 1.2 このまま照明・レーザー・炎・映像を足すと

- **行が増えすぎる。** 照明だけでも「前の列のムービング」「奥のウォッシュ」「客席側のスポット」…と4〜8グループ。レーザー2、炎2、映像1〜2。合わせて25行前後。重なりで段も増えるので、1画面に収まらない
- **インスペクターの枝分かれが増える。** 種類を1つ足すたびに `isXxxLane` と専用の入力欄を `inspector.ts` に足すことになり、管理しやすさの方針（値は1か所）に反する
- **値の種類が噴水の5つで固定。** ムービングライトはズーム・ゴボ・ストロボ、レーザーは図形、炎は長さ…と、持つ値が違う
- **見たい物だけ見る手段が無い。** 花火の山場を詰めるとき、水の行は邪魔。3D でも花火だけ見たい

逆に、**困らない所**：キューの一覧＋組み立て（`compileShow`）という土台は、種類が増えても通用する。花火（`fire`）と水幕（`clip`）を足したときに、すでに「キューの形を種類ごとに足す」やり方が動いている。土台は作り直さなくてよい。

## 2. ほかの道具は、どう分けて、どうまとめているか

確かめ方：公式ページ・マニュアルを読んだ範囲。読めなかった所は「未確認」と書いた。

| 道具 | 何の道具 | 分け方 | まとめ方 | このプロジェクトへの示唆 |
| --- | --- | --- | --- | --- |
| **Depence**（Syncronorm）| 噴水・照明・レーザー・映像・特効の設計と再生 | 分けない。**時間軸1本**に、場面・音・映像・機材グループ・パラメータ・目印のトラック。トラックは**木（ツリー）にまとめられ**、たためる。場面のトラックは**パラメータの種類ごとに分けて**別々に時刻を合わせられる。一部を「入れ子のショー」に出せる | 時間軸そのもの | いちばん近い答え。1本の時間軸＋木でたたむ＋入れ子 |
| **grandMA3**（MA Lighting）| 照明卓（照明・映像・特効） | 演出ファイル（ショーファイル）は1つ。画面は**ビュー（窓の並べ方）**として保存・切り替え。時間軸は「タイムコードショー」で、トラックグループの中にトラック、トラックごとに対象（シーケンス・グループ・マスター…） | 1つのショーファイル。画面は見方の切り替え | 「作業画面のタブ＝窓の並びの保存」。中身は同じ |
| **DaVinci Resolve**（Blackmagic Design）| 映像の編集・色・音・書き出し | **作業ごとのページ**（メディア・カット・エディット・Fusion・カラー・Fairlight・デリバー）。ページで道具がまるごと変わる | 1つのプロジェクト、1本のタイムライン。どのページも同じタイムラインを見る | ページは「**素材の種類**」ではなく「**作業の種類**」で分けている。ここが大事 |
| **QLab**（Figure 53）| 劇場の音・映像・照明の再生 | 1つのワークスペースに複数のキューリスト。1つのリストに音・映像・照明のキューが**混ざって並ぶ**。グループキューで束ねる | ワークスペース。キューの順番が主で、時間軸は従 | 種類が混ざっても「キュー」という1つの形で扱える。ただし時刻で詰める道具ではない |
| **Finale 3D** | 花火の設計（照明・炎・レーザーも足せる） | 花火が主役。照明・炎は DMX の機材として**同じショーに足す**。レーザーは Pangolin を DMX で動かす。一部を「シーケンス」にまとめられる | 1つのショー、1つの点火の台本 | 花火の道具でさえ、ほかの種類を別の道具に分けず同じショーに入れている |
| **Ableton Live／Logic Pro** | 音楽づくり | 分けない。トラックを**グループ（フォルダ）**にまとめて**たたむ**。行の高さを変える。自動操作の行は出し入れできる | 1本の時間軸 | たたむ・高さ・出し入れは、行が多い問題の定番の解き方 |
| **Unreal Engine の Sequencer** | ゲームエンジンの映像 | 大きい作品は**サブシーケンス**に分け、担当ごとに別々に作る。親のシーケンスに並べて全体にする | 親のシーケンス（時間軸上でずらす・切る） | 「部門ごとの別ファイルを親でまとめる」は**多人数のため**の仕組み |
| **After Effects** | 映像の合成 | 一部を**プリコンポーズ**（入れ子のコンポジション）にして1つのレイヤーにまとめる。中はダブルクリックで開く | 親のコンポジション | 入れ子で行を減らす。ただし中と外を行き来する手間が増える |

### 2.1 表から言えること

1. **時間で合わせる道具は、どれも時間軸を1本にしている**（Depence、Ableton、Logic、Resolve、grandMA3 のタイムコードショー）。種類ごとに別の時間軸を持つ道具は、調べた中には無い
2. **行が多い問題は、たたむ・まとめる・出し入れで解いている**（Depence の木、Ableton・Logic のグループ、After Effects の入れ子）。別画面には分けていない
3. **画面を分ける道具（Resolve、grandMA3）も、中身は1つ**。分けているのは「見方」や「作業」。演出の種類ごとに中身を分けている道具は無い
4. **中身まで分ける（Unreal のサブシーケンス）のは、多人数で同時に作るため。** 1人で作るこのプロジェクトには、その理由が無い
5. 本番の現場では、照明卓（grandMA3）・花火の点火機・噴水の制御を**別々の機械**にして、タイムコードで合わせることが多い。これは**担当者と機械が別**だから。このプロジェクトでは、その形は**書き出し**（CSV・DMX・点火表）で受け持てばよく、エディタの形にまで持ち込む必要は無い

## 3. 案の比べ

| 案 | 中身 | 良い所 | 合わない所 | 判定 |
| --- | --- | --- | --- | --- |
| **A. 今のまま行を足す** | 1つの時間軸に、行を足し続ける | 作る量が最小 | 25行で破綻。インスペクターの枝分かれが増え、管理しにくくなる | **やめる** |
| **B. 1つのエディタ＋フォルダ＋作業画面のタブ**（おすすめ） | 時間軸1本。行は種類ごとのフォルダ。上のタブで見方を切り替え | 全体を常に1か所で合わせられる。データは1つ。今の土台をそのまま使える | タブの「見方」の設計が要る。全体のタブでは情報が多い（たたんだ要約で受ける） | **おすすめ** |
| **C. 種類ごとの別エディタ**（照明エディタ、花火エディタ…） | 種類ごとに別の画面・別の時間軸 | 1つ1つの画面は単純 | 合わせる場所が無くなる（どこで全体を見る？）。再生・波形・区間・保存を毎回作り直す。1人で作るのに、本番の現場の「担当ごとに分ける」を真似る理由が無い | **やめる** |
| **D. 種類ごとの別ファイル＋親でまとめる**（Unreal 型） | `lights.json`・`pyro.json`… を親の演出が並べる | ファイルが小さい。多人数なら同時に作れる | 1人には手間だけ増える。どのファイルに何があるか迷う（管理しやすさに反する） | **今はやめる**。ただし「版の重ね方」で一部を使う案は 5.4 |
| **E. Resolve 型のページを種類ごとに** | 水ページ・光ページ・花火ページで道具がまるごと変わる | 見た目が整理される | Resolve のページは**作業**で分けている。**種類**で分けると、水と光を合わせる作業（いちばん大事）がページをまたぐ | **種類では分けない**。作業（会場・書き出し）でだけ分ける |

**B の弱い所も書いておく：**
- 全部を1枚の時間軸に載せるので、時間軸（`timeline.ts`、今 974 行）は大きくなる。種類ごとの描き方（花火の◆と上昇の帯、水幕の映像の名前…）を**種類の表から呼ぶ**形に分けないと、1つのファイルが膨らむ
- 種類によっては、時間軸だけでは作りにくいものがある（レーザーの図形を描く、映像を切る）。これは無理に時間軸でやらず、「素材を作る所」を別にして、時間軸では「どの素材を、いつ出すか」だけを置く（水幕の映像を `clip` で指しているのと同じ）

## 4. おすすめの形（B）の基本設計

### 4.1 画面の構成

```
┌ 上の帯 ──────────────────────────────────────────────────┐
│ [時間軸] [会場] [書き出し]      ← ページ（作業で分ける。中身は同じ演出・会場） │
└──────────────────────────────────────────────────────────┘
時間軸のページ：
┌ 作業画面のタブ ─────────────────────────────────────┐
│ 全体 │ 水 │ 光 │ 花火 │ 映像 │ (＋自分で保存)             │
├────────────┬───────────────────────────────┬─────────┤
│ 3D の画面    │                               │ インスペクター │
├────────────┴───────────────────────────────┴─────────┤
│ 区間・目盛り・波形                                         │
│ ▾ 水        [S][M]  ← フォルダ（たたむと1行の要約）          │
│     グリッド / ウィップ / … / ガイザー                         │
│ ▸ 水幕      ███ ██  ███                                │
│ ▸ 花火      ◆ ◆◆  ◆                                    │
│ ▸ 照明      ▆▆▆  ▆                                     │
│ 全体の見取り（今の navigation の帯）                        │
└──────────────────────────────────────────────────────┘
```

- **ページ**（上の帯）＝作業で分ける。時間軸（今の edit.html）、会場（段階5の venue.html）、書き出し（段階4）。どれも同じ演出ファイルと会場を開く。Resolve のページと同じ考え
- **作業画面のタブ**＝時間軸のページの中の「見方」。中身は1つ。タブが持つのは：
  - どのフォルダを開くか・たたむか・隠すか
  - 3D で何を見せるか（例：「花火」のタブでは水を薄く、カメラは「花火」の席）
  - インスペクターの並び（その種類の入力欄を上に）
  - 「全体」は全部のフォルダをたたんだ要約から始める。ここで全体を見て合わせる
- **フォルダ**＝演出の種類ごと。たたむと1行に、中のキューを重ねた要約（今の見取りの帯と同じ描き方）を出す。各フォルダに **S（ソロ：これだけ見る・3D もこれだけ）** と **M（消す：時間軸で薄く、3D で出さない）**
- **まとめて見て合わせる場所**は3つ：時間軸の「全体」タブ、3D の画面（いつも全部の種類が出る。S/M で一時的に絞る）、組み立て（`compileShow` が全種類を1つの指令にする）

### 4.2 データ（演出ファイル）

**演出ファイルの形は、ほぼ今のまま。** キューの一覧1つ。種類はキューに書かず、**対象の機材の種類から決まる**（花火の行がそうなっている）。

```ts
// 今：Cue = { t, target, set?, macro?, clip?, fire?, ... }
// 案：キューの「形」を3つに整理する（新しい種類はこのどれかに乗る）
//   1. 値を動かす   set / macro / dur / ease / stagger   … 噴水・照明・炎の高さ・レーザーの明るさ
//   2. 一発を出す   fire（花火）／ burst（炎・スパーク・CO2。長さ付き）
//   3. 素材を流す   clip（水幕・映像・レーザーの図形）
```

- `Params`（噴水の5つ）を、**機材の種類ごとの値の一覧**に広げる。`set` の中身は種類が持つ値だけ受け付ける（照明なら dimmer・color・pan・tilt・zoom…）
- 種類を足すたびに `Cue` に欄を足すのは、`fire` と `burst` と `clip` で止める。新しい種類は、この3つの形のどれかに乗せる
- 見方（どのフォルダを開くか、タブ）は**演出ファイルに入れない**。エディタの自動保存（localStorage）に置く。演出の中身と画面の都合を混ぜない
- `version: 2` の演出はそのまま読める（足すだけ。消す欄は無い）

### 4.3 機材の種類の表（1か所に集める）

管理しやすさの方針どおり、**種類を足す手順を「表に1つ足す」にする**。

```
src/fixtures/            （案。今の nozzles.ts の考えを、全種類に広げる）
  index.ts               種類の一覧（登録）
  water.ts               噴水：値の一覧（範囲・単位）、行の色、フォルダ名「水」
  screen.ts              水幕：clip
  pyro.ts                花火：fire。判定は src/pyro/schedule.ts を呼ぶ
  light.ts               照明（後で）
  laser.ts / flame.ts / video.ts（後で）
```

1つの種類が持つもの：

| 持つもの | 使う所 |
| --- | --- |
| 名前・フォルダ名・行の色 | 時間軸のフォルダと行（色は tokens.css の名前を指す） |
| キューの形（値／一発／素材）と値の一覧（範囲・単位・初期値） | インスペクターの入力欄を**表から作る**（今の `isPyroLane` などの枝分かれをやめる） |
| 時間軸の描き方（ふつうの帯／◆と上昇の帯／映像の名前） | `timeline.ts` から呼ぶ |
| 判定（物理・保安距離・速すぎる） | 警告の一覧（C5） |
| 描画・音 | プレイヤー |
| 書き出しのチャンネル | CSV・DMX（段階4） |

会場（`src/venues/`）は今どおり「どの種類の機材を、どこに、何台」を持つ。種類そのものの性質は種類の表、並びは会場。

### 4.4 1人で作るときの流れ（想定）

1. 「会場」ページで機材を置く（段階5）
2. 「水」タブで噴水の振付を作る（今と同じ）
3. 「光」タブで照明（と噴水の LED の色）を作る
4. 「花火」タブで山場の花火を置く
5. 「全体」タブで全部たたんだ要約を見て、山場の重なり・密度を合わせる。3D で通して見る
6. 「書き出し」ページで動画・CSV・点火表を出す

## 5. 判断が要ること

> **2026-11-03 決まった（ユーザー）：** 5.1 は案1（噴水の LED の色は噴水の行のまま。「光」タブでは色だけ見える形で出す）、5.2 は案1（タブは演出の種類で）、5.3 は案1（会場・書き出しは別ページ）、5.4 は案1（Night Lagoon を写して別の版にする。参照して重ねる仕組みは作らない）。

### 5.1 噴水の LED の色は「水」か「光」か
今、色と明るさは噴水の値（`color`・`intensity`）。照明を足すと、「光」タブで噴水の色も合わせたくなる。
- **案1（おすすめ）**：キューは今どおり噴水の行に置く。「光」タブでは噴水の行を**色だけ見える形**で出す（Depence の「パラメータの種類で分ける」）
- 案2：噴水の色を別の行（「水の光」）に分ける。分かりやすいが、行が倍になり、今の演出ファイルの書き直しが要る

### 5.2 作業画面のタブを何で分けるか
- **案1（おすすめ）**：演出の種類で（全体・水・光・花火・映像）。キューが種類に属しているので、迷わない
- 案2：作業の段階で（振付・光・仕上げ）。段階は人によって違い、どのキューがどのタブか決まらない

### 5.3 時間と関係ない仕事を別ページにするか
- **案1（おすすめ）**：会場の編集・書き出しは別ページ（同じ演出と会場を開く）。dev-plan の段階5の `venue.html` と同じ
- 案2：全部 edit.html の中のパネルにする。1画面で済むが、時間軸のページが重くなる

### 5.4 版の重ね方（花火版と Night Lagoon）
花火版の土台を Night Lagoon にするなら、2つのやり方がある。段階3の別チャットで決まっていれば、それに従う。
- 案1：Night Lagoon を**写して**花火版を作る（今のファンタジア版と同じ）。単純。ただ Night Lagoon と二重になる
- 案2：花火版は「Night Lagoon を**下敷きに参照**＋自分のキュー（花火など）を重ねる」。Night Lagoon は承認済みで変えないので、二重にならない。Unreal のサブシーケンス・After Effects の入れ子に近い。ただし読み込みの仕組みが要る

### 5.5 やめたほうがいい案（念のため）
- 種類ごとの別エディタ（案C）、種類ごとの Resolve 型ページ（案E）
- 値ごとの自動操作の行（DAW の automation lane を全部の値に）：行が爆発する。今のキューの帯（区間で値を動かす）のほうが噴水に合う
- Fusion のような点と線でつなぐ編集（ノード）：自由だが、この規模では作る量に見合わない
- Depence をまるごと真似る：立て付け（手前に立つ）とぶつかる。真似るのは「1本の時間軸を木でたたむ」だけでよい

## 6. 進め方（案）

段階3（花火版の演出）の邪魔をしないよう、段階3が終わってから。dev-plan の段階6（エディタの使い勝手）に入れる。

| 順 | 中身 | 確かめること |
| --- | --- | --- |
| 6a | 行に「種類」を持たせ、フォルダにまとめる。たたむ・要約・S/M | `scripts/editor-check.mjs`。たたんでも開いても、演出は1画素も変わらない |
| 6b | 機材の種類の表（`src/fixtures/`）。インスペクターを表から作る。今の水・水幕・花火を移す | 移す前と後で、インスペクターの入力と保存される演出ファイルが同じ |
| 6c | 作業画面のタブ（見方の保存・3D の連動） | タブを切り替えても演出は変わらない |
| 6d | 会場・書き出しのページへの入口（段階4・5と一緒） | — |
| 後 | 照明・レーザー・炎・映像を、表に1つずつ足す | 種類を1つ足すのに触るファイルが、表と描画と会場だけで済むか |

6a・6b は、照明などを足す**前に**やる。6c は、行が増えて困ってからでもよい。
