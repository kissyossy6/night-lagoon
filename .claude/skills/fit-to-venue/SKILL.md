# fit-to-venue（ショーを会場に合わせて組み直す）

このプロジェクトの軸は「誰でも、演出を、自分の規模に合わせて、自由に作れる」（机 → 庭 → 広場 → 湖）。ところが今のショーは湖のために、機材の番号（`grid[88-175]` など）で書かれている。広場で流すと Night Lagoon の 469 キューのうち 265 が何も動かさず、199 は一部だけ動く。机では 319 が動かない。会場に機材が無いもの（扇・花・チェイサー・水幕）と、番号が範囲の外（中帯・後帯）が主な理由。

組み直しは「縮める」ことではない。**ショーの骨組みを残して、配役をやり直す**こと。客が覚えているのは「静かに始まり、山が二段あり、最後が一番大きく、始まりの絵で終わった」という流れで、どの機材が何台だったかではない。

会場ごとの機材・寸法・縮まないもの は `references/venues.md`。

## 流れ

### 0. 何を、どこへ、どこに置くか

- 元のショー（Night Lagoon・ファンタジア版・花火版・エディタで作ったもの）と、行き先の会場を決める
- 組み直したショーは**新しいファイル**にする。元の版は1つも変えない（承認済みの版を守る約束）
- 置き場は**新しいプロジェクト**：`projects/<id>/project.json`（`docs/projects-plan.md`。id は `p-<日付>-<短い乱数>`、`name` は「<元の名前> — <会場の名前>」、`from` は元の版、`show` に組み直したショー）。作り方のスクリプトは同じフォルダに `fit.mjs` として残す（元のショーが変わったら作り直せるように）。`projects/` は GitHub に入らない（個人のデータ）
- 会場はショーの `venue` で決まる。開くのはプロジェクト一覧から。プロジェクトの仕組みがまだ動いていなければ、`shows/<会場のid>/<名前>.json` に置いてエディタの「ファイル → 読み込む」で開き、そう伝える

### 1. 測る

```bash
node .claude/skills/fit-to-venue/scripts/reach.mjs --show=lagoon --venues=plaza
```

会場の機材（グループ・台数・種類・高さ・名前の付いた並び・花火の台）と、場面ごとに「動く／動かない／一部だけ」、動かない理由の多い順が出る。どの場面が崩れるかを先に見る。

### 2. 骨組みを書き出す

元のショーの `docs/show-plan.md`（演出台本）から、会場が変わっても残すものを表にする：

| 残すもの | 元のショーでは | この会場では |
| --- | --- | --- |
| エネルギー曲線（密度0〜5） | | |
| 同期点（MUSIC の時刻） | | 同じ時刻のまま |
| ご褒美（一度きりの手） | ガイザー 0.7→0.8→全高10本 | |
| カラースクリプト | 1場面1色＋差し色 | 同じ |
| 暗と谷 | | 同じ時刻 |
| 始まりと終わり（種火） | | |

時刻・色・暗転・谷は**会場に関係なく残せる**。曲は同じだから。変わるのは「誰が踊るか」と「大きさ」だけ。

### 3. 配役をやり直す

役ごとに、この会場で一番近い機材を当てる。例（湖 → 広場）：

| 湖の役 | 湖の機材 | 広場で当てるもの | 足りないとき |
| --- | --- | --- | --- |
| 土台・床の形 | grid 3帯×88 | `@前列`・`@中列`・`@後列`（各12） | 帯の数は同じ3つ。1帯の中の時差は台数で割り直す |
| バレエ（隊形） | whip 24 | `@首振りの列`（8） | 隊形は同じ（扇・交差・波）。開きの角度は小さい機材の傾き（20°）まで |
| 追いかけっこ | chaser 弧と輪 | 無い → 前列のグリッドで端から走らせる | |
| 面・華やぎ | fan・flower | 無い → その場面の主役を首振りかグリッドの形に | ご褒美が1つ減るなら、別の手を前倒ししない |
| 最大の大技 | geyser 10 | `@真ん中`（1） | 回を追って大きくする段は、本数でなく高さと周りの機材の数で作る |
| 物語 | 水幕・山 | 無い | 物語の場面は「谷」として、色と少数の機材で静かに。映像の代わりを水で描こうとしない |
| 空 | 花火 | 広場は保安距離が足りない（2.5号でも100 m） | 入れない。最後の手札は水で |

- **段とご褒美の順番を守る**：機材が減ると、最後の一撃が中盤より小さくなりやすい。手札表（show-director）を会場の手札で作り直し、最後に一番大きいものが残るように配る
- **主役は1場面1群**のまま。機材が少ない会場ほど、全部を同時に出したくなる。全機材は全体の15%前後だけ
- **的は `@名前` で書く**。番号で書くと、会場の部品を1つ動かしただけで意味が変わる。名前の無い並びが要るなら、venue.html で部品に名前を付ける（fountain-layout）か、ユーザーに聞く

### 4. 時間と大きさを合わせる

小さい会場では、水が上がる・落ちる時間が短い（粒の飛ぶ時間は高さから計算されるので、描き方は自動で縮む）。ただし、**キューの側の決まりは湖の大きさのまま**で、自動では縮まない。

- 暗転の先取り「約3秒前に消し始める」は湖の 12〜30 m の柱の話。4 m の柱は約1秒、0.1 m は約0.2秒で落ちきる（落ちる時間 ≈ √(2h/9.81)＋空気の分）。同じ3秒前に消すと、暗転の前に長い暗い間ができる
- 首振り 90°/秒、弁 0.2/0.25秒、LED の変化の下限（色0.6秒・明るさ0.9秒・点く0.12秒）は会場で変えていない。小さい実機は速いかもしれないが、まだ測っていない。速くしたくなったら、決める前にユーザーに聞く
- 机・庭の機材の数値は全部「仮」（実物に合わせていない）。3D はそのことを画面に出している。報告でもそう書く

### 5. 書く

`<名前>.fit.mjs` に、元のショーから新しいショーを作る関数を書く（show-compare の make-proposal と同じ形：`export default async function (show, ctx) { ... return show }`）。

- 先頭で `show.venue = '<会場のid>'`、`show.title` を「<元の名前> — <会場の名前>」に
- 元のキューを1つずつ置き換える（的を `@名前` に、高さ・時差を直す）か、場面ごとに消して書き直す。場面ごとのほうが配役の考えが通りやすい
- 各キューの `label` に場面と役を書く（「第1トゥッティ 主役 首振りの扇」）
- 作る：`node .claude/skills/show-compare/scripts/make-proposal.mjs --base=lagoon --edit=projects/<id>/fit.mjs --out=<作業フォルダ>/show.json`、できた `show.json` を `project.json` の `show` に入れる

### 6. 確かめる

1. **動かないキュー**：`node .claude/skills/fit-to-venue/scripts/reach.mjs --file=<作業フォルダ>/show.json --venues=plaza`。見るのは先頭の「自分の会場でも何も動かさないキュー」で、これを 0 にする（ファイルの会場が広場になると、下の「全体」は広場で動くキューだけを数えるので、0 でも安心できない。的を書き換えただけの試しでは、ここに扇・チェイサーなど 173 が残った）。残すなら理由を書く
2. **会場の決まり**：venue.html で会場を開き、止める・赤が無いこと（会場を変えていなければ、組み込みの3会場は警告0）
3. **撮る**（show-compare）：同じ時刻を、湖の元のショーと、この会場の新しいショーで並べる

   ```bash
   node .claude/skills/show-compare/scripts/capture.mjs --out=shots/fit-plaza \
     --src=now:show=lagoon --src="new:file=<作業フォルダ>/show.json&cam=audience" \
     --t=10,45,63,92,106.6,130,163,175.5,178.6,206
   ```

   席の名前は会場ごとに違う（小さい会場は自動の席 audience・wide・eye・left・right・aerial だけ）
4. **段**：`sheet.py bright` で、山へ向かって明るさが上がっているか、最後が一番か
5. **首振りの上限**：make-proposal の出す数が 0
6. **他の版**：元の版のファイルは触っていないので変わらないはず。コードを触ったときだけ show-compare の「変わっていないことを確かめる」

### 7. 渡す

結論を先に：どの会場で、何キューが動くようになったか（265 → 0 など）、配役をどう変えたか（表）、無くした手と代わりの手。今｜案の絵と切り替えページ。机・庭の数値が仮であること。ユーザーが自分で見る方法（プロジェクト一覧から開く。`play.html?project=<id>`）。

## やってはいけないこと

1. 元の版（Night Lagoon・ファンタジア版・花火版）を書き換えて会場に合わせる
2. 時刻・暗転・谷・色まで会場に合わせて動かす（曲は同じ。変えるのは配役と大きさ）
3. 番号（`grid[0-11]`）で的を書く
4. 無い機材の場面を、全機材の同時出しで埋める
5. 最後の一撃が中盤より小さいまま渡す
6. 水幕の物語を水の形で描こうとする
7. 小さい会場の数値を「本物どおり」と言う（仮の値）
8. 保安距離の足りない会場に花火を入れる
