# 報告の型と、聞くこと・決めてよいこと

## 報告の型

ユーザーの言葉：「私が何を判断したら良いかシンプルに教えて」「もっと端的に教えて私のやることも教えて」「結論で端的に何を見たら良いのか」。

```markdown
<結論 1〜2行：何が変わったか／何がわかったか>

**見てほしい所**：<時刻と、そこで何が違うか。絵へのリンク>

**決めてほしいこと**：<1つだけ。無ければこの行ごと消す>

<今｜案の絵（compare.jpg・motion.jpg）、切り替えページ ab.html>

**確かめたこと**：静止画（11か所）、連続コマ（91.6〜94秒）、型・エディタのチェック、他の版0画素
**確かめていないこと**：音つきの再生、<ほか>

**自分で見るには**：<URL か、エディタの「ファイル → 〇〇を読み込む」>
```

- 日本語で書く。計画や報告を英語で下書きしない
- 内部の記号（R1・C3・H2・6b・D5・P2 など）は使わない。使うなら毎回「H2（着水のしぶき）」のように言葉を添える。ユーザーは「1.5って何だっけ」と聞き返している
- モードや機能の名前を新しく付けるときは、先にユーザーに確かめる（「本来」と「機材前提」は通じなかった。照明モードは「リアル（機材どおり）」「理想（見栄え優先）」）
- 数字は「明るさ 37 → 52」「265 → 0 キュー」のように短く
- 長い経緯は `docs/handoff.md` の追記へ。チャットには結論だけ

## 聞くこと

- 外の素材（録音・映像・画像・参考ページ）を保存・ダウンロードする前（ファイル名・出典・大きさ・ライセンス）。「毎回聞いてほしい」
- 承認済みの版（Night Lagoon・ファンタジア版）の中身を変えるとき。共通のコードを変えて全部の版の中身が変わるときは、変える前に言う
- ショーの構成を大きく変える前（演出台本を見せてから）
- 新しい名前を付けるとき
- 講評を3周目に回すとき

## 決めてよいこと（聞かない）

- 見た目の細かい所は、調べたことをもとに決める（「調査した内容をもとに、自由に決めてほしい。ただ見た目の雰囲気だけを言ってたつもり」）
- 書き出しの形式の細部（「正直あまり気にしてないので、何でもok」）
- 描き方・エンジンの改善をどの版に入れるか（全部に入れる）

## そのほか

- 1つ頼まれたら1つ作る。目線のカメラを頼まれて、見上げ・寝そべり・目線の3つを作ったら「目線だけにして」と言われた
- 比べるときは、ボタンで切り替えるか、2つの画面に分ける（「ボタンで切り替えながら比較したい」「2画面でそのままと変えたので分けて欲しい」）
- 値と物は1か所に置き、置き場と手順を短く書く（「基本的には管理しやすくしてほしい」）
- トークンを使いすぎない。読むのは要る所だけ。長くなったら新しいチャットへ（`docs/handoff.md` を先に読む）
