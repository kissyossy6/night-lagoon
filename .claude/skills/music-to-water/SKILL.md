# music-to-water（音楽を読んで水に移す）

振付家の仕事の半分は聴くことだ。Longwood Gardens の初代噴水振付家 Colvin Randall は、同じ曲の録音を15種以上聴き比べてから水を付けた。客が「合っている」と感じるのは、全部の音に水が反応したときではない。**強く合う点がいくつかあり、曲の形（区間とフレーズ）が水の形と一致している**ときだ。

このプロジェクトの音楽まわり（`MUSIC`、`SECTIONS`、波形解析、`follow`／`onsets`／`snap`）は `.claude/skills/show-director/references/project-api.md` の4章。原則の出典と数値は `references/sync.md`。

## 1. 音楽地図を作る

振付の前に、曲を次の層で書き出す。自動解析は候補出しに使い、最後は人の耳（録音を聴く・波形を見る）で確定する。プロも拍とキューはタイムラインの上で手で置く。

| 層 | 何を書くか | どう取るか |
| --- | --- | --- |
| 区間 | 導入・主題・トゥッティ・間奏・ブレイク・終止。感情の一言 | 音量の大きな段差、自己相似（同じ主題の戻り）、耳 |
| フレーズ | 4〜8小節のまとまりの始まりと頂点 | 旋律の休み、ノベルティの小さな山、耳 |
| 追う声部 | 区間ごとに **1つ**（クラリネットの旋律、金管の打撃、ピアノ独奏…） | 耳。スペクトル重心で音色の硬さの見当をつける |
| 同期点 | 強く合わせる瞬間。3分なら大小合わせて10前後、最大のものは3〜4 | 一番大きな立ち上がり、無音の後の一撃、フレーズの頂点 |
| 拍・打撃 | ダウンビート、強いオンセット | 拍の追跡（テンポが揺れる曲は人がタップ）、spectral flux |
| 無音・ブレイク | 音が床に落ちる区間 | 音量の谷 |

書き方の例（`src/show/song.ts` の `MUSIC` と同じ「秒＋何が起きるか」）：

```
0–16   導入  追う声部：クラリネット（トリル→グリッサンド→主題）  同期点：グリッサンドの頂点
45.25  オーケストラが入る  追う声部：弦の旋律
62.25  第1トゥッティ（+6dB）  同期点★：頭の一撃  追う声部：金管の打撃
```

## 2. 音を水と光に割り振る

**拍は光で、フレーズは水で。** LED は速く変わる（色の変化0.6秒・点く0.12秒が下限）が、12m の柱が9割の高さに届くまで約1秒かかる。拍や細かい打撃を水の高さで追うと、いつも遅れて見える。打撃は intensity のパルスと色のバンプ、手前の低い帯の pop、chaser の噴き出しで打つ。水の高さと隊形は2〜8拍かけた起伏とフレーズで動かす。

**区間ごとに追う声部を1つ。** 全部の音に反応させる（ミッキーマウシング）と作り物に見える。導入でクラリネットを追うなら、伴奏には反応しない。振付家は区間ごとにドラム・旋律・声を追い分ける（ChoreoMaster, SIGGRAPH 2021）。

**音の性質と水の性質を対応させる**（人に共通の感覚の対応。噴水への当てはめは推測を含む）：

| 音 | 水・光 |
| --- | --- |
| 音量（ならした） | 全体の高さ、動いている本数 |
| 音高が上がる | whip が起き上がる、波の山が上・中央へ |
| 柔らかい音色（クラリネット・弦） | 滑らかな単柱、ゆっくりした sway |
| 硬い・ざらついた音色（金管・シンバル） | 泡立つ fan・flower、chaser、霧 |
| 低音の重さ | 奥の帯・山・geyser の「量」（高さより量） |
| 速い長調 | 明るく彩度の高い暖色寄り |
| 遅い短調 | 暗く青寄り |
| 無音 | 全消灯（水は前に止め、光を無音の瞬間に落とす） |

**帯域をそのまま列に流さない。** 低中高を3列の高さに割り当てる「カラーオルガン」は、実機で試した研究で「跳ねる水にしかならない」と結論された（タリン工科大学 2019）。このショーにも以前 `floor()`（奥＝低音、中＝中音、手前＝高音）があったが、2026-10-26 に全場面から外した。待機中の背景には使えるが、主役にしない。帯ごとの高さの差は場面ごとに決めた形（奥を高く）で固定し、全体の高さをならした音量で動かす（今の `follow(a, b, ROW.front, 'level', min, max)` を帯ごとに書く形）。

**同じ主題には同じ動き。** 主題が戻ったら最初の隊形・色を戻す。以前の `formations()` は強いオンセットごとに型を順に回していたので、同じ主題でも違う隊形になった（2026-10-26 に外し、隊形はフレーズの頭に置く形にした。`docs/show-plan.md` の第1トゥッティ）。

**対位法は大きな対比として。** 伴奏が細かく刻む所で whip はゆっくり弧を描き、光だけが刻む。最後の和音の伸ばしで水が静かに下りていく。あえて合わせないのは「重さ」「時間が止まる」を出したいとき。

## 3. 先取りする

花火は開花の時刻から打ち上げ時間を引いて点火する。水も同じ。ただし実際の噴水は「頂点を音に合わせる」ほど先取りしていない。Bellagio と Dubai を0.2秒刻みで測ると（`references/sync.md` の実測）：
- **照明（色・明るさ）は拍とほぼ同時（±0.2秒）**
- **水の弁は拍と同時か、最大0.4秒前に開く**。高さが届くのは0.5〜1.5秒後（高い水ほど遅い）
- ならした音量と水の量は、水が **0.7〜1.5秒遅れ**で一番よく合う。水は拍ではなく**フレーズの大きさ**に付いていく
- 消すのは休符の上、点けるのは拍の上

つまり客は「噴き出しの瞬間」を音と結びつけ、頂点が少し遅れることは気にしない。これを基準に：
- 噴き出しの瞬間を打撃に合わせる：拍と同時〜0.4秒前（ガイザー・chaser・pop）。今の実装はオンセットちょうどで、これに近い
- 満ちた形そのものを見せ場にしたいとき（扇が開ききる、壁が立ちきる瞬間を和音に）だけ、立ち上がり時間だけ前（grid 約1.0秒、whip 約1.7秒、geyser 約2.3秒）。これは例外として使う
- **入りは、水を音楽と一緒に育てる**：直前が暗い入りで、水（形）を暗闇で先に作り、照明を拍の上で入れると、客には拍の瞬間に形が丸ごと現れる（Bellagio の「照明の瞬断」と同じ考え方）。ただしこのユーザーは、ファンタジア版の 92.1秒をこの型にしたら「いきなり出現して不自然」と言い、水が音楽に合わせて伸びていく入りを選んだ（91.6秒のピックアップから中央から光ったまま伸ばし、94.1秒で床と金の渦を一段上げる）。新しく入りを作るときは、まず「ピックアップの拍から水を伸ばし、拍で一段上げる」型にする。暗闇で立てる型は、曲がはっきり「無音→一撃」のときだけ、今｜案で見せて選んでもらう
- `follow`：実物でも水は音量に0.7〜1.5秒遅れて付いていく。今の実装の遅れ（先読みなし＋0.25秒刻みの区間の終わりへ動く＋水の上昇で1.1〜1.3秒）は実物の範囲の中にある。先読みを足すなら控えめに（0.3〜0.5秒）。「ずれて見える」の原因は、遅れより「追う声部がない」「反応する音が多すぎる」「拍とフレーズの層がない」ほうを先に疑う
- 隊形替えは動きの時間の半分ほど前から
- 無音の前：水は約3秒前に止め始め（grid が落ちきるまで約3.1秒）、無音の瞬間に光を落とす

数値は fountain-physics の表。どれだけ先取りするのが良く見えるかは、0／−0.25／−0.5／−1.0秒を撮り比べて目で決める。迷ったら少し早めに（映像が音より少し早いほうが自然に感じる。ITU の許容は映像が先 約125ms・音が先 約45ms）。

## 4. 同期を確かめる

**キューの時刻ではなく、見える出来事の時刻で測る。** キューが音の時刻ちょうどでも、水の頭が目標に届くのは1〜3秒後。測るのは「水が目標高さの9割に届いた時刻」「LED が上がった時刻」とオンセットの差。目標は ±0.1秒（やや早め寄り）。

今の `scripts/sync-check.mjs` はキュー側で測っている。見える出来事で測るように直すか、`node scripts/show-shot.mjs` で同期点の前後を 0.1秒刻みで撮って、目で確かめる。

## チェックリスト

- [ ] 音楽地図があり、区間ごとに追う声部が1つ決まっている
- [ ] 同期点が少なく強い（最大級は3〜4回）。全部のオンセットに反応していない
- [ ] 拍・打撃は光と低い水、フレーズは高さと隊形で表している
- [ ] 帯域をそのまま列の高さに流し続けていない
- [ ] 同じ主題に同じ型が戻っている
- [ ] 光は拍の上（±0.2秒）、水の噴き出しは拍と同時〜0.4秒前
- [ ] 無音の前に水を止め、光を無音の瞬間に落としている
- [ ] 同期を見える出来事で確かめた
